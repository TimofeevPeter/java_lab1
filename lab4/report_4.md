## **Задача 1.3**

**Обобщённый интерфейс сравнения.**
Создать обобщённый интерфейс `Сравнимое<T>`, описывающий контракт сравнения двух объектов, и реализовать его для разных типов данных (числа и строки).

**Алгоритм решения.**
Интерфейс объявляет метод `int сравнить(T other)`. Конкретные классы `СравнимоеЧисло` и `СравнимаяСтрока` используют ключевое слово `implements` для соблюдения этого контракта. Сравнение чисел выполняется через вычитание значений, а строк — через сравнение их длин. Возвращаемое значение подчиняется стандартному соглашению Java: отрицательное число (если `this` меньше `other`), ноль (если равны), положительное число (если `this` больше `other`).

## **Задача 1.6**

**Обобщённый неизменяемый список.**
Модифицировать класс `ImmutableValueList` из предыдущей лабораторной, сделав его обобщённым, чтобы тип хранимых элементов задавался при создании объекта через параметр `<T>`.

**Алгоритм решения.**
Класс объявлен как `ImmutableValueList<T>`. Из-за стирания типов (type erasure) в Java внутреннее хранилище реализовано через `Object[] values` с одновременным сохранением `Class<T> type` для безопасного приведения типов. Конструкторы используют метод `Arrays.copyOf()` для создания независимых копий массивов, гарантируя структурную неизменяемость списка. Метод `get(int index)` использует `type.cast()` для безопасного извлечения элемента типа `T`, а метод `toArray()` возвращает клон массива, предотвращая внешние модификации.

## **Задача 2.4**

**Универсальное заполнение числового списка.**
Создать метод, заполняющий список числами от 1 до 100, способный принимать списки с разной параметризацией.

**Алгоритм решения.**
Метод `fillWithOneToHundred` использует маску типа (wildcard) `List<? super Integer>`. Это позволяет передавать в метод списки `List<Integer>`, `List<Number>` или `List<Object>`, обеспечивая типобезопасную запись (`write`) целых чисел в коллекцию, тип элементов которой является `Integer` или одним из его предков. Перед заполнением список очищается методом `clear()`.

## **Задача 3.1**

**Преобразование элементов списка (Функция).**
Реализовать универсальный метод, который применяет заданное преобразование к каждому элементу списка и возвращает новый список результатов другого типа.

**Алгоритм решения.**
Создан обобщённый интерфейс `Transformer<T, P>` с методом `P apply(T value)`. Универсальный статический метод `transform` принимает исходный `List<T>` и объект, реализующий этот интерфейс. Внутри метода создаётся новый `ArrayList<P>`, который заполняется результатами вызова `transformer.apply(item)` для каждого элемента исходного списка в цикле `for-each`. Это демонстрирует принцип передачи поведения через интерфейс: алгоритм обхода не знает конкретной логики преобразования.

## **Задача 3.2**

**Фильтрация элементов списка.**
Создать метод, который возвращает новый список, содержащий только те элементы исходного списка, которые удовлетворяют заданному логическому условию.

**Алгоритм решения.**
Определён интерфейс `Condition<T>` с методом `boolean test(T value)`. Универсальный метод `filter` перебирает элементы исходного списка и добавляет их в результирующий `ArrayList<T>` только в том случае, если `condition.test(item)` возвращает `true`. Конкретные реализации условия (например, `StringLengthAtLeast3` или `IsPositive`) инкапсулируют логику проверки, оставляя сам алгоритм фильтрации универсальным и независимым от типа данных.

## **Задача 3.3**

**Сокращение (свёртка) списка.**
Разработать метод, который сворачивает список значений типа `T` в одно итоговое значение типа `T` с помощью переданной операции объединения.

**Алгоритм решения.**
Используется интерфейс `Combiner<T>` с методом `T combine(T left, T right)`. Метод `reduce` принимает исходный список, начальное значение (`identity`, например, `0` для суммы или `""` для конкатенации строк) и объект `Combiner`. Алгоритм инициализирует аккумулятор значением `identity` и последовательно обновляет его: `result = combiner.combine(result, item)`. Использование параметра `identity` гарантирует корректную работу метода (возврат нейтрального элемента, а не `null` или исключение) при передаче пустого списка, что является требованием задания.
